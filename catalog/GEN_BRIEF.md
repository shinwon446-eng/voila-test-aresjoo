# 새 카탈로그 상품 자료 만들기 (작업 지시서)

VOILA 는 박스를 열어 실물 상품을 받는 서비스다. 박스 320개(브랜드마다 하나)에 상품을 100개씩 채운다.
너는 카테고리 하나를 맡아 그 카테고리의 공통 상품과 박스 20개의 상품 목록을 만든다. 글 자료(JSON)만 만든다. 사진은 만들지 않는다.

저장소: `C:\Users\hyun1\OneDrive\바탕 화면\VOILA-test-aresjoo`, 앱은 `web/` 아래다. 명령은 `web/` 에서 돌린다.

## 읽을 것
- `web/lib/catalog2/manifest.json`: 박스 320개. 네 카테고리의 20개를 본다(`category`, `slug`, `brand`, `title`, `price`, 참고용 `top`, `low`). 이 파일은 고치지 않는다.

## 만들 파일
1. `web/lib/catalog2/data/<category>/pool.json`
   ```json
   { "items": [["<category>-p-meguiars-g7164", "맥과이어스 골드 클래스 카 샴푸 64oz", "Meguiar's Gold Class Car Wash 64oz", "美光金级洗车液 64oz", 12.99], ...] }
   ```
2. 박스마다 `web/lib/catalog2/data/<category>/<slug>.json`
   ```json
   { "slug": "car-rolls-royce", "items": [["car-rolls-royce-phantom-series-ii", "롤스로이스 팬텀 시리즈 II", "Rolls-Royce Phantom Series II", "劳斯莱斯幻影 Series II", 505750], ...], "use": [] }
   ```
   `use` 는 빈 배열로 둔다. 스크립트가 채운다.

상품 한 줄은 다섯 칸이다: `[번호, 한국어 이름, 영어 이름, 중국어(간체) 이름, 값(달러)]`.

## 박스 하나가 어떻게 100개가 되나
박스의 상품 = 그 박스의 자기 상품(`items`) + 공통 상품에서 스크립트가 고른 것(`use`).
- **자기 상품**: 그 브랜드의 본품과, 그 브랜드가 실제로 파는 소품. 15개 이상 90개 이하. 브랜드에 제품이 많으면 40개에서 70개를 쓴다. 적은 브랜드(차종이 여덟뿐인 자동차 브랜드)는 있는 만큼만 쓰고 지어내지 않는다.
- **공통 상품(pool)**: 같은 카테고리의 다른 브랜드 상품과 사이드 소품. 박스 20개가 나눠 쓴다. 220개에서 300개.
  이 카테고리에 박스가 있는 브랜드의 제품은 공통 상품에 넣지 않는다(그 브랜드 박스의 자기 상품과 겹친다). 박스가 없는 브랜드의 제품과, 어느 브랜드 박스에나 어울리는 소품을 넣는다.

## 가격 구간 (P = 박스 가격)
확률은 값과 박스 가격의 비율로 정해진다. 박스 하나에 아래 구간이 고르게 있어야 한다. 괄호는 100개 가운데 목표 수.

| 구간 | 값의 범위 | 목표 |
|---|---|---:|
| 낮은 A | 5달러 이상 0.5P 미만 | 16 |
| 낮은 B | 0.5P 이상 P 미만 | 14 |
| 1배 | P 이상 1.5P 미만 | 12 |
| 2배 | 1.5P 이상 3P 미만 | 14 |
| 4배 | 3P 이상 6P 미만 | 12 |
| 8배 | 6P 이상 12P 미만 | 10 |
| 15배 | 12P 이상 25P 미만 | 8 |
| 40배 | 25P 이상 60P 미만 | 6 |
| 100배 | 60P 이상 150P 미만 | 4 |
| 250배 | 150P 이상 400P 미만 | 2 |
| 500배 | 400P 이상 | 2 |

- 자기 상품은 되도록 높은 구간부터 채운다(브랜드의 대표 제품이 박스의 큰 결과가 되게). 낮은 구간은 브랜드 소품이 있으면 넣고, 없으면 공통 상품이 채운다.
- 그 카테고리에 그런 값의 실물이 없으면 높은 구간은 비워도 된다. 다만 박스마다 가장 값진 상품은 15P 이상이어야 하고, 될 수 있으면 40P 이상이 좋다.
- **공통 상품은 이 카테고리의 박스 가격 전부를 받쳐야 한다.** 박스 가격이 50, 100, 250이면 5달러부터 수만 달러까지 값이 고르게 퍼져 있어야 한다. 값을 두 배씩 늘려 가며(5, 10, 20, 40 ... ) 구간마다 12개에서 18개가 있게 한다. 특히 5달러에서 박스 최고가 사이가 촘촘해야 낮은 구간이 채워진다.

## 지킬 것
1. **실제로 있는 제품만 쓴다.** 모델 이름은 정확히 적는다(연식, 용량, 크기, 레퍼런스 번호, 세트 번호). 있는지 확실하지 않으면 넣지 않는다. 브랜드가 실제로 팔지 않는 굿즈를 지어내지 않는다.
2. **값**은 미국 달러 기준의 대략적인 신품 정가나 통상 거래가다(2025년에서 2026년). 센트까지의 숫자(예: 12.99, 505750). 5 이상. 같은 제품은 어디서나 같은 값이다.
3. **색만 다른 것은 다른 상품이 아니다.** 용량, 크기, 연식, 등급, 소재처럼 값이 달라지는 차이만 다른 상품으로 센다.
4. **이름 셋**: 한국어는 한국에서 쓰는 표기(브랜드 한글 표기 + 모델), 영어는 공식 이름, 중국어는 간체(통용 이름이 없으면 영어 모델명을 그대로 쓴다). 세 이름 모두 비우지 않는다. 한 박스 안에서 영어 이름이 겹치면 안 된다.
5. **번호**: 소문자, 숫자, 하이픈만. 64자 이하. 공통 상품은 `<category>-p-` 로, 박스의 자기 상품은 `<slug>-` 로 시작한다(예: `car-p-thule-wingbar-evo`, `car-rolls-royce-ghost-series-ii`). 겹치면 안 된다.
6. 과장, 광고 문구, 이모지를 이름에 넣지 않는다. 가운뎃점(·)과 줄표(—)를 쓰지 않는다.
7. 포켓몬 카테고리: 박스는 캐릭터별이다. 자기 상품은 그 포켓몬이 나오는 실제 카드(세트 이름과 카드 번호, 등급이 있으면 등급까지)와 그 포켓몬의 공식 상품이다. 공통 상품은 부스터 박스, 엘리트 트레이너 박스, 슬리브, 바인더 같은 포켓몬 카드 게임 상품과 다른 포켓몬의 카드다(박스가 있는 캐릭터의 카드는 빼고).

## 일하는 순서
1. manifest 에서 네 카테고리의 박스 20개와 가격을 본다.
2. `pool.json` 을 먼저 만든다. 만든 뒤 `node scripts/catalog2/build-index.mjs <category>` 로 공통 상품에 문제가 없는지 본다.
3. 박스 파일을 하나씩 만든다(자기 상품만, `use` 는 빈 배열).
4. `node scripts/catalog2/fill.mjs <category>` 로 100개를 채운다. "100개를 못 채웠다"가 나오면 공통 상품의 그 값대를 늘린다.
5. `node scripts/catalog2/build-index.mjs <category>` 로 검사한다. 박스마다 "통과"가 나와야 한다. 문제가 나오면 고치고 4번과 5번을 다시 한다.
6. 스무 박스가 모두 통과하면 끝이다.

## 하지 않는 것
- 위의 자료 파일 말고 다른 파일을 고치지 않는다(manifest, 스크립트, 앱 코드 포함). 커밋하지 않는다. 빌드나 개발 서버를 돌리지 않는다.
- 이 PC 의 셸은 Git Bash 이고 명령이 포장 도구를 거치면서 heredoc 이 깨진다. 파일은 파일 쓰기 도구로 만든다(`cat <<EOF` 로 만들지 않는다). 경로에 한글과 빈칸이 있으니 따옴표로 감싼다.
- JSON 은 UTF-8 로 쓴다. 파일 하나가 커지면 박스마다 따로 쓰는 것이라 괜찮다.
