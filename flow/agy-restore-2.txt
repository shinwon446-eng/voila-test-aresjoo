  성공 화면(232-263행)과 실패 화면(265-281행) 모두 aria-live 영역이나 role="status"가 없습니다.
  시트 제목(`v-sheet-title`)이 "업그레이드에 성공했습니다" 또는 "업그레이드에 실패했습니다"로 변경되지만, 앞서 키보드 조작 검증에서 확인된 바와 같이 초점이 다이얼로그나 본문으로 이동하지 않으므로 스크린 리더가 제목 변경을 자동으로 낭독하지 않습니다.
  비교: Opening.tsx 233행은 `<div className="v-op-result" aria-live="polite" aria-atomic="true">`를 사용하여 결과 노출 시 실시간 낭독을 보장하고 있으나, UpgradeSheet.tsx는 해당 구조가 누락되어 있습니다.

6. 움직임 줄이기 (Reduced Motion)

- UpgradeSheet.tsx 131행:
  `setStep(drawn && !window.matchMedia("(prefers-reduced-motion: reduce)").matches ? "draw" : "result");`
  prefers-reduced-motion이 켜져 있을 때 1.8초의 추첨 연출을 건너뛰고 즉시 결과 단계(`result`)로 진입하도록 정확하게 처리되어 있습니다.
- web/app/upgrade.css 27행:
  `@media (prefers-reduced-motion: no-preference) { .v-up-bar[data-moving] .v-up-mark { animation: v-up-move var(--dur) linear both; } }`
  CSS 애니메이션 또한 no-preference 미디어 쿼리 안에서만 실행되도록 보호되어 있습니다.
- ScrollRow.tsx 29행 (개선 필요):
  `el.scrollBy({ left: dir * Math.max(160, el.clientWidth * 0.8), behavior: "smooth" });`
  후기 줄 이동 단추 클릭 시 `behavior: "smooth"`가 강제되어 있습니다. prefers-reduced-motion 설정 환경에서는 사용자의 전역 감속 선호에 맞춰 `behavior: "auto"`로 전환하는 것이 권장됩니다.

7. 권장 수정 사항 우선순위 목록

(1) 배포 차단 항목 (Deployment Blockers)

1. UpgradeSheet 결과 단계 초점 이동 및 스크린 리더 실시간 안내 누락
- 위치: web/components/flow/UpgradeSheet.tsx 116행, 203행, 232행, 265행
- 내용: `step === "draw"`에서 `step === "result"`로 바뀔 때 초점이 `document.body`로 방치되며 결과 상태가 스크린 리더에 읽히지 않습니다. `step === "result"` 진입 시 다이얼로그 패널에 초점을 맞추거나(panel.current.focus()), 결과 컨테이너에 `role="status"` 및 `aria-live="polite"` 속성을 부여해야 합니다.
- 기대 효과: 시각 장애인 및 키보드 사용자가 추첨 완료 즉시 성공/실패 여부를 인지할 수 있고, 곧바로 주 행동 단추(USDT로 받기 또는 박스 보러 가기)로 접근 가능합니다.
- 회귀 위험: 매우 낮음. JSX 속성 및 useEffect 초점 호출 보강 수준입니다.

2. UpgradeSheet 추첨 중 Escape 키 스킵 동작 미지원
- 위치: web/components/flow/UpgradeSheet.tsx 171행, web/components/ui/Sheet.tsx 15행
- 내용: `step === "draw"` 동안 Sheet의 locked 속성으로 인해 Escape 키가 완전히 차단됩니다. Opening.tsx(135행)와 Reveal.tsx(76행)의 패턴과 동일하게, 연출 진행 중 Escape 입력 시 `onClose()` 대신 `setStep("result")`를 호출하여 결과를 즉시 확인할 수 있도록 수정해야 합니다.
- 기대 효과: 키보드 사용자가 불필요하게 1.8초를 대기하거나 Tab 키로 건너뛰기 링크를 찾아 헤매지 않고 Escape 키 하나로 즉시 결과를 확인할 수 있습니다.
- 회귀 위험: 매우 낮음. 추첨 결과 정산은 이미 run() 호출 시점에 확정되어 있으므로 연출 중단에 따른 데이터 불일치가 없습니다.

3. 보관함 및 여러 개 결과 화면에서 UpgradeSheet 종료 시 초점 유실
- 위치: web/components/inventory/InventoryScreen.tsx 187행, web/components/box/Reveal.tsx 306행
- 내용: UpgradeSheet를 열 때 이전 상세 시트를 먼저 닫아버려(`closeItem()`, `pick(null)`), 업그레이드가 끝나거나 시트를 닫았을 때 트리거 요소가 DOM에 없어 초점이 `document.body`로 상실됩니다. 상세 시트를 닫기 전 원래 목록 행의 요소를 기억하거나, 이전 시트를 unmount하지 않고 UpgradeSheet 뒤에 두거나, 닫힐 때 원래 행으로 초점을 명시적으로 복구해야 합니다.
- 기대 효과: 업그레이드 종료 후 키보드 탐색 위치가 문서 시작 지점으로 튕기지 않고 보관함 목록의 해당 상품 위치로 유지됩니다.
- 회귀 위험: 낮음. 모달 중첩 관리(modalStack)와의 호환성 확인이 필요합니다.
