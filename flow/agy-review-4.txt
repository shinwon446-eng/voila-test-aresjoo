`DESIGN.md`와 `flow/MELT_SPEC.md`를 기준으로 이번 변경(USDT로 받기 중심 개편, 나온 상품 화면, 세 단계 블록체인 검증)의 커밋되지 않은 코드 및 화면 스크린샷(`qa/work/melt3`)을 부품 구조와 유지보수 관점에서 검토한 결과입니다.

### 1. TakeSheet 가 다섯 군데에서 쓰이는 방식

`web/components/flow/TakeSheet.tsx`는 묶음 선택 시트 부품으로서 다섯 개 기능 흐름(실제 호출 컴포넌트 6곳)에서 쓰이고 있습니다.

1. **박스 화면 (`web/components/box/BoxScreen.tsx` 줄 309-310)**
   - 잔액 부족 시(`short && need.heldCount > 0`, 줄 202) 주 단추를 누르면 `takingHeld` 상태로 열립니다.
   - `ids`를 넘기지 않아 보관 중인 상품 전체를 대상으로 하며, `onTaken` 콜백 없이 장부 스토어 반응에 맡깁니다.
2. **단일 결과 화면 (`web/components/box/Opening.tsx` 줄 303-304)**
   - 다음 개봉 잔액 부족 시(`stuck && need.heldCount > 0`, 줄 271) 주 단추로 `heldTaking` 상태를 켭니다.
   - 보관 중인 상품 전체 대상이며 `onTaken`은 없습니다.
   - **지적**: 단일 결과 화면에서 방금 나온 상품 1개를 USDT로 받는 일은 `TakeSheet`를 열지 않고, 자체 인라인 `Confirm` 모달(줄 302)과 `settleTake` 호출로 처리합니다.
3. **여러 개 결과 화면 (`web/components/box/Reveal.tsx` 줄 280-281)**
   - 두 가지 진입점을 하나의 `TakeSheet`로 처리합니다:
     - 방금 나온 상품 받기(줄 251): `ids={waiting.map((r) => r.ownedId)}`를 넘겨 이번 개봉 결과만 선택 시트에 담습니다.
     - 다음 개봉 잔액 부족(줄 135): `ids` 없이 열어 보관 중인 상품 전체를 담습니다.
   - `onTaken={batchTaken}`(줄 130)을 전달하여 받은 금액을 결과 화면의 영수증 상태(`taken` 맵)에 즉시 반영합니다.
   - **지적**: 개별 상품 카드를 눌렀을 때의 1개 받기는 `TakeSheet`가 아니라 단독 `Confirm` 모달(줄 283)로 인라인 처리합니다.
4. **보관함 화면 (`web/components/inventory/InventoryScreen.tsx` 줄 168-169)**
   - 보관 중 탭 상단의 주 단추 클릭 시 `batch` 상태로 열립니다(줄 111).
   - `ids` 없이 전체 보관 상품을 대상으로 하며, `onTaken` 없이 스토어 갱신으로 목록을 다시 그립니다.
   - **지적**: 개별 상품 상세 시트의 1개 받기는 `Confirm` 모달(줄 171)과 `settleTake`로 인라인 처리합니다.
5. **출금 화면 (`web/components/wallet/WithdrawScreen.tsx` 줄 256)**
   - 보관 상품이 있을 때 금액 칸 위의 링크(줄 239)를 누르면 `taking` 상태로 열립니다.
   - `doneLabel={t("take.withdrawBack")}`를 넘겨 완료 단추 문구를 출금 복귀 안내로 바꿉니다.
   - `onTaken={onTaken}`(줄 89-95)을 통해 새로 들어온 크립토 잔액을 `withdrawPrefillUsdt`로 계산하여 출금 입력 칸(`amountText`)에 자동으로 채웁니다.
6. **잔액 시트 (`web/components/flow/BalanceSheet.tsx` 줄 58)**
   - 머리줄의 잔액 버튼으로 열린 잔액 시트 안에서 주 단추를 누르면 같은 자리에서 `TakeSheet`(`open && taking`)로 전환됩니다.

**부품 구조 평가**:
- **잘된 점**: `ids`(대상 범위 한정), `onTaken`(정산 후 콜백), `doneLabel`(완료 단추 문구)의 3가지 속성으로 다양한 화면 요구사항(결과 화면 묶음, 출금 자동 채움, 보관함 일괄 받기)을 깔끔하게 흡수했습니다.
- **문제점**:
  - `TakeSheet`가 다중 선택 전용으로만 쓰이다 보니, 1개 상품 받기를 처리하는 세 화면(`Opening.tsx` 줄 302, `Reveal.tsx` 줄 283, `InventoryScreen.tsx` 줄 171)에서 거의 완전히 동일한 `Confirm` 모달과 핸들러 코드가 3벌 중복 작성되어 있습니다.
  - `BalanceSheet.tsx`(줄 58)에서 `TakeSheet`의 `onClose`로 `close`(`closeBalance`)를 넘겨, 사용자가 상품 선택을 취소하고 시트를 닫으면 이전 단계인 잔액 시트로 돌아가지 않고 전체 시트가 닫혀버립니다.

### 2. 중복된 계산 (takeAmountOf 와 기존 sell)

1. **환급액 계산식의 인라인 중복**
   - 새 함수: `web/lib/takeBatch.ts` 줄 27  
     `export const takeAmountOf = (item: Pick<OwnedItem, "valueUsdt">): number => +(item.valueUsdt * REFUND_RATE).toFixed(2);`
   - 기존 함수: `web/lib/products.ts` 줄 50  
     `export const sellValueOf = (item: Pick<ProductItem, "kind" | "value">): number => +(item.kind === "cash" ? item.value : item.value * REFUND_RATE).toFixed(2);`
   - **문제점**: `takeAmountOf` 유틸리티 함수가 새로 추가되었음에도 불구하고, 같은 변경 내역 안의 화면들에서 이를 쓰지 않고 직접 인라인 계산을 수행하고 있습니다.
     - `web/components/inventory/InventoryScreen.tsx` 줄 76: `const takeAmount = current ? +(current.valueUsdt * REFUND_RATE).toFixed(2) : 0;`
     - `web/components/inventory/InventoryScreen.tsx` 줄 120: `+(item.valueUsdt * REFUND_RATE).toFixed(2)`
     - `web/components/box/BoxScreen.tsx` 줄 235: `+(current.value * REFUND_RATE).toFixed(2)`
     - `web/lib/vault.ts` 줄 18: `resaleEstimate`의 `Math.round(i.valueUsdt * REFUND_RATE * 100) / 100`

2. **정산 실행 함수의 중복 (중요)**
   - `web/lib/openingSettle.ts` 줄 33: `settleTake(ownedId: string)`
   - `web/lib/takeBatch.ts` 줄 101: `settleTakeMany(ownedIds: string[])`
   - **문제점**: 두 함수 모두 계정별 장부 잠금(`withLedgerLock`), 개발용 결함 주입(`devOpeningFault`), 중복 연타 방지(`inflight`), 이미 판매된 상품 확인(`already`), `takeUsdt` 호출을 수행합니다. `settleTake(id)`는 사실상 `settleTakeMany([id])`의 단일 원소 특수 케이스인데도 완전히 별도의 함수와 별개의 `inflight` 맵으로 중복 구현되어 있습니다.

### 3. 상태 저장소 (flowStore)의 책임

`web/stores/flowStore.ts` 줄 9-20:
```ts
interface FlowState {
  charge: boolean;
  menu: boolean;
  balance: boolean;
  // ...열림/닫힘 액션들
}
```

**구조 및 유지보수 지적**:
- **이름과 책임의 괴리**: 이름은 `flowStore`(흐름)이지만, 실제로는 최상위 시트 3개의 boolean 열림 상태만 토글하는 단순 전역 오버레이 저장소입니다.
- **시트 관리 방식의 비대칭**:
  - `ChargeSheet`와 `BalanceSheet`는 `flowStore`로 열리고 `AppShell.tsx`에 전역으로 마운트되어 있습니다.
  - 반면 이번 개편의 핵심 시트인 `TakeSheet`와 검증 시트인 `VerifySheet`는 `flowStore`에 포함되지 않고 5-6개 개별 화면에 각자 `useState` 로컬 상태로 마운트되어 있습니다.
  - 특히 `BalanceSheet.tsx` 줄 51, 58을 보면, `USDT 충전하기`는 전역 스토어 액션(`openCharge()`)으로 전환하는 반면, `USDT로 받기`는 컴포넌트 로컬 상태(`setTaking(true)`)로 전환합니다. 시트 전환의 주체가 전역과 지역으로 갈려 있어 일관성이 떨어집니다.

### 4. 문구 키의 구성 (messages/v.*.json)

1. **`take`와 `reveal` 도메인 키의 분산과 중복**
   - 새 네임스페이스 `take.*`에 24개 키가 추가되었으나, 기존 `reveal` 네임스페이스와의 정리가 덜 되어 있습니다.
   - `take.title`과 `reveal.takeTitle`이 모두 `"USDT로 받기"`로 중복 정의되어 있습니다.
   - 정작 USDT 받기 단추 라벨로는 `take.*`의 키가 아니라 `reveal.take`(`"USDT로 받기 ({amount})"`)를 여러 화면(`TakeSheet.tsx` 줄 126, `Opening.tsx` 줄 292/302, `Reveal.tsx` 줄 135, `InventoryScreen.tsx` 줄 151/171)에서 계속 빌려 쓰고 있어 키 응집도가 떨어집니다.
2. **네비게이션 라벨 키의 예외 분기**
   - `web/components/shell/AppShell.tsx` 줄 33:
     `const navLabel = (key: (typeof NAV)[number]["key"]): string => (key === "wins" ? "wins.title" : "nav." + key);`
   - 다른 6개 메뉴는 전부 `nav.*` 규칙(`nav.boxes`, `nav.inventory` 등)을 따르는데, 나온 상품만 `wins.title`을 직접 참조하는 컴포넌트 레벨 하드코딩 분기가 들어가 있습니다. `nav.wins` 키를 정의하여 일관성을 맞추는 편이 안전합니다.

### 6. 줄이거나 합칠 수 있는 것

1. **`settleTake`와 `settleTakeMany`의 통합**:
   - `web/lib/openingSettle.ts`의 `settleTake`를 `settleTakeMany([ownedId])`의 단일 결과 래퍼로 축소하면 중복 로직 40줄 이상과 분리된 두 개의 `inflight` 맵을 하나로 합칠 수 있습니다.
2. **단일 상품 받기 확인창(`Confirm`)의 공용화**:
   - `Opening.tsx`(줄 302), `Reveal.tsx`(줄 283), `InventoryScreen.tsx`(줄 171)에 중복된 단일 받기 `Confirm`을 공용 컴포넌트(`TakeConfirmModal` 등)로 분리하거나 `TakeSheet`가 단일 ID도 처리하도록 통합할 수 있습니다.
3. **인라인 환급액 계산의 `takeAmountOf` 치환**:
   - `InventoryScreen.tsx`(줄 76, 120), `BoxScreen.tsx`(줄 235)의 인라인 식을 `takeAmountOf`로 통일하여 중복 수식을 제거할 수 있습니다.
4. **`VerifySheet` 마운트 중복 정리**:
   - 6개 화면(`BoxScreen`, `Opening`, `Reveal`, `InventoryScreen`, `WinsScreen`, `VerifyScreen`)에 똑같이 선언된 `useState<VerifyRecord | null>(null)`와 `<VerifySheet ... />`를 더 단순한 구조로 정리할 여지가 있습니다.
5. **중복된 옛 문구 키 정리**:
   - 사용처가 겹치는 `reveal.takeTitle`, `reveal.takeDesc`를 정리하고 단추 문구를 일원화할 수 있습니다.

1. **정산 실행 함수 통합 (`settleTake`를 `settleTakeMany` 기반으로 단일화)**

3. **인라인 환급액 계산을 `takeAmountOf` 호출로 일원화**

   - 이유: 금지 문자 검사가 `take.*`와 `balanceSheet.*`에만 걸려 있어 신규 추가된 `wins.*`, `verify.chain.*` 등의 메시지 파일이 검사 사각지대에 놓여 있습니다.
