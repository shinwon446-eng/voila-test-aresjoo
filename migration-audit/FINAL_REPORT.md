## A. 기존 아키텍처 진단

세부는 `ARCHITECTURE.md`.

- 스택: Next.js 14(app router, 정적 내보내기), React 18, TypeScript, zustand(persist, localStorage), next-intl. 지금 닿는 화면의 움직임은 전부 CSS 와 `setTimeout` 단계다. framer-motion 을 가져오는 파일 24개 가운데 라우트에서 닿는 것은 움직임 없는 래퍼 하나다.
- 저장소의 `.html` 파일은 0개. 정적 산출물은 HTML 1,092개(언어 화면 1,089, 루트 1, 404 둘).
- 옛 홈과 옛 개봉 연출은 소스에 남아 있으나 어느 라우트도 그리지 않는다(닿지 않는 TS 파일 97개). 지우지 않았고 동등성 판단에서 뺐다.
- 직접 DOM 을 만지는 파일 10개는 Codex 가 파일마다 판정했다: React 가 가진 DOM 을 덮어쓰는 곳이 없어 그대로 둔다(`analysis/codex-a-routes-events-state.md` 6절).
- 그래서 "마이그레이션이 필요한 영역"은 없었다. 한 일은 전수조사, 원본 대조 도구, 조사에서 근거가 나온 곳만 고치기다.

로컬에서 배포와 같은 방식(`GITHUB_PAGES=true next build`)으로 기준 커밋을 다시 빌드해 배포 사이트와 견줬다: 촬영 3,099장 가운데 2,920장이 픽셀까지 같고 178장은 값 1~2 의 차이, 1장은 39픽셀(0.005%). 구조 차이(크기, 줄 수, 2px 넘는 자리, 글꼴, 빠진 그림)는 0건(`screenshots/diff/baseline-noise/SUMMARY.md`). 그 뒤의 대조는 잡음이 가장 적은 로컬 기준 빌드를 원본으로 썼다.

## E. 애니메이션 검증

`harness/motion.mjs`: 17경우(한 개와 다섯 개와 열 개, 보통과 움직임 줄이기, 짧게 보기, 건너뛰기, CPU 4배 감속, 결과의 크기별: 박스값보다 싼 것, 조금 높은 것, 20배 이상)를 세 번씩, 끼어들기 5종. 한국어 폭 390 과 영어 폭 1440. 프레임은 100ms 마다. 커밋 `f830d9e` (`motion/compare-after-final3/`, `-en-1440/`).

- 34개 비교 전부에서 같음: 사건 순서, CSS 애니메이션의 집합, 결과 크기별 효과, 소리와 진동의 호출 목록(확정 전의 누름 소리 포함), 장부를 쓰는 때, 끝난 뒤 장부, 끼어들기 17단계.
- 길이: 보통 조건에서 50ms 를 넘는 칸이 없다(-17 ~ +12ms). 느린 기기 흉내(CPU 4배)의 영어 1440 에서 두 칸이 +36, +62ms 였고 여섯 번씩 다시 재니 범위가 겹쳤다.
- 한쪽으로 치우친 작은 차이: 결과 빌드가 누름부터 개봉 화면까지 1~9ms, 50달러 박스의 상품 결과에서 공개까지 2~12ms 늦다. 한 프레임(16ms) 안쪽이다. 후기 구역을 감추고 재면 사라진다(박스 화면에 후기 다섯 건이 생긴 값이다).
- 원본의 순서: 누름 → 잔액과 수량 검증 → 결과 확정과 장부 기록(누른 뒤 14~16ms) → 개봉 화면(28~33ms) → 기대 약 530ms → 충격 약 150ms → 퇴장 약 170ms → 결과 공개 → 약 350ms 뒤 단추 풀림. 장부는 언제나 연출보다 먼저다.
- 끼어들기(도중 다시 누름, 동시에 세 번, 떠났다 돌아옴, 새로 고침, 뒤로 가기): 개봉 거래 1건, 보관함 기록 1개, 다음 회차 1. 못 본 결과는 다시 뽑지 않고 다시 보여 준다.
