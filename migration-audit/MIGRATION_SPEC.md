## 0. 무엇을 하고 무엇을 하지 않는가

코드가 이미 전부 React 라서 화면을 새로 옮길 것이 없다(`ARCHITECTURE.md` 1절). 결과 브랜치에 들어가는 변경은 아래 세 묶음뿐이다. 그 밖의 파일은 기준 커밋과 한 글자도 다르지 않아야 한다.

| 묶음 | 내용 | 원본과의 관계 |
|---|---|---|
| W1 | 샘플 후기(박스마다 80~400건) | 의도된 차이. 2026-10-12 밤 파운더 지시. 후기 자리만 달라진다 |
| W2 | 원본의 기존 결함 가운데 P1 이고, 재현됐고, 서버 없이 고칠 수 있고, 작은 것 | 의도된 차이. 지시문 11절 "P0 와 P1 은 모두 수정". 결함마다 커밋 하나 |
| W3 | React 구조 결함(훅 순서, 정리 빠짐, 언마운트 뒤 응답, 늦은 비동기 응답). 정상 경로의 화면과 동작은 그대로 | 차이 없음이 목표. 지시문 9절 |

하지 않는 것: 옛 화면(닿지 않는 파일 97개)을 지우거나 되살리기, Tailwind 로 옮기기, 라이브러리 추가와 교체, 컴포넌트 다시 쪼개기, 디자인 손보기, 확률과 지급 계산 손대기, P2 와 P3 결함 고치기(백로그로 남긴다), 서버가 있어야 하는 기능을 된 것처럼 만들기.

## 2. W2 기존 결함 가운데 고치는 것

`PARITY_ISSUES.md` A부의 번호다. 고치기 전에 그 결함을 재현하는 테스트를 먼저 쓰고(실패하는 것을 본 뒤), 고친 뒤 통과를 본다. 돈 계산식과 반올림은 바꾸지 않는다.

| 번호 | 결함 | 원본 위치 | 고치는 방법 | 화면 차이 |
|---|---|---|---|---|
| E-01 | 출금 취소 때 차감되지 않은 금액까지 환불된다 | `WithdrawScreen.tsx:123`, `walletStore.ts:197` | 차감이 실패하면 출금 요청을 만들지 않고 그 자리에 알린다. 취소 환불은 실제로 차감된 기록에만 한다 | 정상 경로는 같다 |
| E-06 | 지갑 내역에 박스 열기와 받기 거래가 나오지 않는다 | `WalletScreen.tsx:66`, `opening.ts:109`, `claim.ts:24` | 이 계정의 장부 키에 든 거래는 계정 번호가 없어도 보여 준다(장부 키가 이미 계정별이다). 다른 계정의 것이 섞이지 않는 것을 테스트로 | 지갑 내역에 줄이 늘어난다(의도) |
| E-08 | 모바일에서 같은 자리를 두 번 누르면 받기 확인창을 건너뛴다 | `components/ui` 의 확인창(`Sheet.tsx:32-51`), 결과 화면의 0.35초 잠금 | 확인창이 뜬 직후 짧은 동안 확정 단추가 눌리지 않게 한다(결과 화면과 같은 장치, 같은 길이) | 없음 |
| E-03, E-04 | 계정 화면의 비밀번호 바꾸기와 탈퇴가 끝까지 가지 않는다 | `AccountSheets.tsx:61`, `:90`, `browserAccount.ts:232`, `:147` | 서비스에 이미 있는 인증 단계 함수에 연결하는 것으로 끝나면 고친다. 새 화면을 여럿 만들어야 하면 고치지 않고 까닭을 적는다 | 시트에 단계가 생길 수 있다(의도) |
| E-14 | 달러 표시에서 음수 금액의 빼기 표시가 통화 기호 뒤에 온다(`$-50`) | `lib/formatCurrency.ts:20`, `:45-48`, `WalletScreen.tsx:70` | 빼기 표시를 통화 기호 앞으로 옮긴다(`-$50`). 숫자와 단위를 나눈 표기(`splitCurrency`, `splitNative`)도 같게 맞춘다. 등급은 P2 라 0절의 원칙으로는 남길 항목이지만, E-06 을 고치면서 지갑 내역의 박스 열기 줄마다 이 꼴이 보이게 되어 함께 고친다(2026-10-12 총괄 결정) | 음수 금액의 글자가 `$-50` 에서 `-$50` 으로 바뀐다(의도). 양수와 0 의 글자는 같다 |

고치지 않고 남기는 P1:
- E-02 (저장 공간이 차면 열기는 성공으로 보이나 저장되지 않는다): 고치는 방법은 저장 줄이기인데, 2026-10-12 저녁에 만든 것을 파운더가 버리기로 정했다. 미해결 P1 로 최종 보고에 적는다.
- E-26 (출금이 이용 기준을 검사하지 않는다): 기준을 강제할지는 제품 결정이다(`flow/MELT_SPEC.md` 가 범위 밖으로 남긴 것). 최종 보고에 적는다.
