VOILA — ZERO-LOSS REACT MIGRATION & PIXEL-PERFECT PARITY AUDIT
0. 역할과 최상위 목표
당신은 이번 프로젝트의 총괄 아키텍트이자 최종 품질 책임자인 Claude Opus 5.5입니다.
Codex (6.1-sol high)와 AGY (3.8 Flash high)를 독립적인 전문 에이전트로 활용하십시오. 실제 환경에서 제공되는 모델 및 호출 방법을 먼저 확인하고, 해당 모델을 호출할 수 없다면 다른 모델을 호출했다고 허위 보고하지 마십시오.
최종 목표는 현재 VOILA를 구성하는 모든 시각 요소, 인터랙션, 애니메이션, 데이터, 상태 전환, 비즈니스 로직을 손실 없이 React 아키텍처에 보존하는 것입니다.
참조 사이트:
https://shinwon446-eng.github.io/voila-test-aresjoo/ko/
참조 저장소:
https://github.com/shinwon446-eng/voila-test-aresjoo
이번 임무는 디자인 혁신이나 전면 재설계가 아닙니다.
원본과 동등하게 동작하는, 유지보수 가능한 React 코드베이스를 완성하고 이를 객관적 증거로 검증하는 작업입니다.
완료 기준은 다음과 같습니다.

* 기존에 구현된 모든 접근 가능한 화면과 UI 상태를 보존한다.
* 모든 인터랙션과 사용자 여정이 기존과 동일하게 작동한다.
* 이미지, 폰트, 아이콘, 색상, 간격, 반응형 배치를 보존한다.
* 애니메이션의 타이밍, 연출, 상태 전환을 보존한다.
* 상품 카탈로그, 가격, 확률, 후기, 검증 및 보관함 로직을 보존한다.
* 기존 백로그와 미구현 계획을 현재 구현 상태와 명확히 구분한다.
* 중복 코드는 줄이되 추상화를 위해 기존 동작을 희생하지 않는다.
* 구현 결과를 브라우저에서 실제 실행하여 원본과 대조한다.

화면이 비슷하게 보이는 것은 성공이 아닙니다.
원본과 동일하게 보이고, 동일하게 작동하며, 내부 계산도 동일해야 성공입니다.
1. 기존 아키텍처를 먼저 확인할 것
코드 작성 전에 실제 저장소를 분석하십시오.
이 저장소에는 이미 Next.js, React, TypeScript, Tailwind CSS, Framer Motion, Zustand 등의 기술이 존재하는 것으로 확인됩니다.
따라서 HTML을 무조건 처음부터 React로 다시 작성하지 마십시오.
다음 순서로 판단하십시오.

1. 이미 React로 구현된 코드는 보존한다.
2. 독립적인 HTML/CSS/JavaScript 부분만 필요한 경우 React로 전환한다.
3. 직접 DOM을 조작하는 부분은 React 상태 및 생명주기와의 충돌 여부를 검토한다.
4. 기존 CSS를 Tailwind로 기계적으로 변환하지 않는다.
5. 기존 라이브러리와 구현을 재사용할 수 있다면 불필요하게 교체하지 않는다.
6. Next.js에서 Vite나 다른 프레임워크로 전환하지 않는다. 명백한 기술적 필요와 검증된 이점이 없다면 현행 구조를 유지한다.
7. 불필요한 전역 상태 관리, 라이브러리 추가, 추상화 계층을 만들지 않는다.

리팩터링 자체가 목적이 아니라 기능 및 시각적 동등성을 갖춘 구조화가 목적입니다.
작업 시작 전에 다음 문서와 디렉터리를 실제로 확인하십시오.

* DECISION_LOG.md, RELEASE-READINESS.md

* 현행 소스와 실제 배포 빌드에 사용된 코드

과거 분석 문서는 최신 상태가 아닐 수 있습니다.
특히 개편 전 UI 인벤토리를 현재 화면의 절대 기준으로 취급하지 마십시오.
