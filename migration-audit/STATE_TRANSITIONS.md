### 0.3 칸의 뜻

- 사례마다 초기 상태, 사건과 입력, 전제조건, 상태 변화, 데이터 변화, 화면 변화, 오류와 취소, 영속성과 새로 고침 뒤, 근거, 참여자 id, 일치, 확인, 덮는 시험을 적는다. 분석가가 따로 적지 않은 칸은 "따로 적힌 것 없음"으로 두거나 통합 담당이 채웠다(채운 것은 그렇게 적었다). 영속성 칸이 일반 규칙으로 채워진 사례는 그 사례에서 새로 고침을 따로 해 본 것이 아니다.
- 경로는 전부 `web/` 기준이다. 저장 키의 줄임말(W 지갑, I 보관함, J 개봉 기록장, F 추첨 값과 회차, S 설정, C 통화, R 후기, A 계정 목록, SS 세션, M 확인 대기 표시, L 고른 언어)은 `INTERACTION_MATRIX.md` 0.4절과 같다.
- 상태 이름은 개봉 상태 기계(`lib/openingFlow.ts:99-130`)의 것이다: READY, CONFIRMING, PURCHASE_PROCESSING, OUTCOME_COMMITTED, OPENING, REVEALED, SETTLING, SETTLED, INSUFFICIENT_BALANCE, PURCHASE_FAILED, SETTLEMENT_PENDING, SETTLEMENT_FAILED, RECOVERY_REQUIRED.
- 덮는 시험: `tests/이름.test.ts` 는 화면 없이 도는 단위 시험, `scripts/capture/이름.mjs` 는 개발 서버의 화면을 누르는 검수 스크립트다. 분석가가 시험의 제목을 읽고 대응시킨 것이고, 시험을 다시 돌려 본 것은 아니다. "감사 하네스: H:글자"는 `migration-audit/harness/flows.mjs` 의 시나리오이고 배포 사이트에서 돌린 기록이 `flows/before-deployed/` 에 있다. "하네스 motion.mjs ...(정의됨)"은 그 경우가 정의돼 있으나 이 문서를 쓰는 때에는 배포 사이트의 결과 폴더가 없었다는 뜻이다.
- 이 사이트의 계정과 장부는 전부 이 브라우저 안의 시험 장부다(`lib/account.ts:47-48`). 메일을 보내지 않고 밖으로 나가는 요청이 없다.

연출의 끝에 걸려 있는 것은 넷이다: 봤음 표시, 상태 기계의 REVEALED 뒤 전이, 자동 받기의 시작, 단추의 잠금. 지갑 처리와 결과 계산은 연출의 끝을 기다리지 않는다. 자동 받기는 돈을 움직이지만 결과를 바꾸지 않고, 못 보고 떠났다가 다시 보는 결과에는 돌지 않는다(`components/box/Opening.tsx:170`).

MISSION 5장이 적은 아홉 단계(입력, 검증, 결과 확정, 연출 시작, 중간 효과, 결과 공개, 보상 확인, 받기 또는 보관, 다음 준비)와 실제 순서가 다른 곳이 하나 있다. 실제로는 "보상 확정"이 3단계에 함께 끝난다. USDT 결과는 구매와 같은 순간에 잔액에 들어가고, 상품은 같은 순간에 보관함에 들어간다. 결과가 드러난 뒤에 따로 지급하는 단계가 없다. 지시문대로 원본의 순서를 따른다.

회차에 대해: 회차는 차감보다 먼저 쓰인다(`lib/opening.ts:58`). 그 뒤의 단계가 던지면 지갑과 보관함은 통째로 되돌리지만(`lib/opening.ts:111-116`) 회차는 되돌리지 않는다. 코드에서 읽은 것이고, 그런 실패를 만들어 실행하지는 않았다. 쓰기가 전부 막혀 구매가 시작되지 않을 때는 회차도 그대로다(04:o10).

| 못 본 결과의 상품이 확률표에 없는 경우(S-104), 같은 화면에서 query 만 바뀌는 경우(S-110), 계산 도중의 입력 변경(S-112), 로그아웃 요청의 실패(S-114), 남은 구독(S-115) | 코드로만 읽었다. 화면으로 만들지 못했다 |
| 가입, 로그인, 계정 시트(S-001 에서 S-017 의 대부분) | 분석가의 실행만 있다. 통합 담당은 계정을 만들거나 비밀번호를 넣는 시나리오를 다시 돌리지 않았다 |
| 기존 시험을 이번에 다시 돌린 결과 | 통합 담당은 `web/tests` 를 돌리지 않았다. Codex 가 돌린 기록이 있다(CX-F-003: 398개 가운데 통과 397, 건너뜀 1) |

## 부록 A. 원본에 있는 결함을 적은 사례

다른 통합 담당이 발견 사항 목록에 연결할 수 있게 번호만 모았다. 등급은 여기서 매기지 않는다.

- S-012: 다른 탭의 로그아웃이 storage 사건으로 전해지지 않는다(CL F-04, CX-P1-06)
- S-013: 다른 탭이 로그아웃한 것을 모르는 탭에서 구매가 된다(CL F-04)
- S-015: 비밀번호 바꾸기가 언제나 실패한다(CL F-06, CX-P1-03)
- S-016: 탈퇴가 언제나 실패한다(CL F-06, CX-P1-04)
- S-048: 다른 탭의 변화가 이 탭의 화면 잔액에 전해지지 않는다(CL F-03)
