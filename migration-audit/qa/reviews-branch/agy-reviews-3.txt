- 누락 발견:
  홈 박스 카드(BoxList.tsx 120행)에서는 ratingSummary(box.slug)를 호출할 때 방문자가 작성한 후기 점수(extra)를 넘겨주지 않습니다. 따라서 스위치를 껐을 때 방문자가 해당 박스에 후기를 작성했더라도 홈 화면 카드에는 평점과 후기 수가 반영되지 않고 숨겨지며, 박스 상세 화면에서만 나타나는 불일치가 발생합니다.

(6) 320개 박스 카드의 요약 생성 비용 (Cost of generating summaries for 320 box cards)
- 파일: web/lib/reviewSamples.ts 124-167행, 178-184행
- 성능 실측 결과:
  320개 전체 박스 요약 생성(coreOf 실행) 시 최초 실행 시간이 13.75ms에 불과합니다. cores 캐시 적중 후에는 320개 전체 순회에 0.1ms 미만이 소요됩니다.
- 가벼운 근거:
  coreOf는 무거운 문자열 생성이나 덱 셔플을 일절 하지 않고, typed array(Uint16Array, Uint8Array, Uint32Array)와 누적 확률 이진 탐색만으로 점수 분포(dist)를 계산하므로 연산 비용이 극도로 낮습니다.

(7) 캐시의 메모리 점유 (Memory of the caches)
- 파일: web/lib/reviewSamples.ts 122행(cores), 211행(built), 496행(order)
- 메모리 실측 결과:
  - cores: 320개 박스 전체 뼈대 캐싱 시 힙 증가량 약 12MB (typed array는 박스당 약 2KB로 매우 작으나 V8 객체 오버헤드 포함).
  - built: 텍스트가 실제로 생성되는 공간입니다. 10개 박스(각 10건) 빌드 시 약 4.5MB, 10개 박스(각 전체 풀사이즈) 빌드 시 약 12.4MB, 320개 박스를 전부 풀사이즈로 빌드하면 약 57.8MB의 힙을 점유합니다.
  - order: Float64Array(75245)로 약 600KB 점유.
- 문제점:
  built 맵에 LRU나 캐시 상한(eviction)이 없습니다. 사용자가 여러 박스를 계속 탐색하거나 모아보기 화면을 스크롤할수록 메모리가 영구 누적됩니다.

(8) 결정론성 (Determinism)
- 파일: web/lib/reviewSamples.ts 70-91행, 498-504행
- 검증 결과:
  FNV-1a 32비트 해시와 Mulberry32 PRNG를 정수 비트 연산으로만 구현하여 브라우저와 Node.js, V8/JSC 환경 간 동일한 난수 시퀀스를 완벽하게 보장합니다.
  newestOrder()에서 Float64Array 키를 생성할 때 ageMin * 262144 + b * 512 + i 방식으로 상위 18비트에 박스 인덱스와 리뷰 인덱스를 고유 패킹하여 시간 동점 시에도 절대 순서가 흔들리지 않도록 정밀하게 설계되어 있습니다.

(9) 카탈로그 사진 이중 노출 이슈
